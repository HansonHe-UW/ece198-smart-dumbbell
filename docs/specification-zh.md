
# Smart Dumbbell — Preliminary Specification v0.1
智能哑铃初步规格｜ECE 198 · Group 57

## 1. 目标、范围与约束

**目标：** 制作一个自制空心智能哑铃，帮助用户执行预设的弯举运动计划，自动记录次数，并在运动过程中持续测量心率、向电脑传输数据。

**目标用户：** CCCARE 居家运动参与者。第一阶段使用小组成员或学生志愿者进行工程测试；测试结果不代表已验证适合所有老年用户。

| 项目 | 第一版定义 |
|---|---|
| 支持动作 | Bicep curl（二头肌弯举），一次只追踪一只哑铃 |
| 动作识别 | 哑铃端运行机器学习模型，区分 `curl`、`idle`、`other` |
| 必须实现 | 动作识别、自动计数、运动中心率检测、屏幕反馈、无线传输、电脑记录 |
| 结构 | 自制可拆卸空心外壳，内部固定主板、电源和传感器 |
| 预算 | 全组自购总支出不超过 **CAD 100，包含税和运费** |
| 不包含 | 握力／肌肉力量测量、康复效果预测、全身姿势评估、自动调整运动处方 |
| 文档状态 | 所有性能数字均为**拟定验收目标**，不是已实现结果或老师规定 |

本规格描述 pitch 中的一套 concept；另一套 concept 仍需单独介绍。

## 2. 功能需求

`MUST` 表示第一版必须实现；未通过测试时应标记为未完成，不能隐式删减要求。

| ID | 优先级 | 需求 |
|---|---|---|
| FR-01 | MUST | 用户可在电脑端设置目标次数，并同步到哑铃；演示默认值为 10 次。 |
| FR-02 | MUST | 提供开始、暂停／继续、结束操作。暂停时不增加次数。 |
| FR-03 | MUST | 连续采集三轴运动数据，保留时间信息供训练和测试使用。 |
| FR-04 | MUST | 模型在微控制器上推理；电脑用于训练和记录，不承担正常使用时的动作分类。 |
| FR-05 | MUST | 仅在识别为弯举且检测到完整运动周期时增加一次计数；同一周期不得重复计数。 |
| FR-06 | MUST | 静止、拿起、放下和无关摆动不得直接作为有效弯举计数。 |
| FR-07 | MUST | 在持续运动过程中采集光学信号并更新心率估计；不能仅在组间静止时测量。 |
| FR-08 | MUST | 心率信号质量不足、失去接触或数据过期时，显示“信号不足”，数值记录为无效，不能继续显示旧数值作为当前心率。 |
| FR-09 | MUST | 屏幕显示当前次数／目标次数、会话状态、心率及其有效状态、无线连接状态。 |
| FR-10 | MUST | 达到目标时给出明确视觉提示；继续运动时仍记录实际次数，不把计数锁死在目标值。 |
| FR-11 | MUST | 经 Wi-Fi 将运动与心率数据发送到电脑；断网后本地识别、计数和显示继续运行。 |
| FR-12 | MUST | 电脑显示实时数据，并保存可导出的 CSV 记录及会话摘要。 |
| FR-13 | MUST | 采样、模型推理、心率计算、显示和通信采用分时或并发调度，避免心率处理长时间阻塞动作采样。 |

**完整一次弯举的操作性定义：** 从校准的低位开始，上举到规定演示高位，再返回低位。高低位阈值由训练和校准数据确定，不把“识别为 curl 的一个时间窗口”直接当作一次动作。

## 3. 硬件、结构与数据流

### 硬件基线

| 部件 | 数量 | 来源与用途 |
|---|---:|---|
| Arduino Nano ESP32，带排针版 | 1 | 自购；主控、模型推理、Wi-Fi |
| Grove ADXL335 | 1 | 学校借用；三轴加速度采样 |
| GY-MAX30102 | 1 | 学校借用；运动中心率可行性验证 |
| OLED | 1 | 学校基础套件；本地显示 |
| 按钮 | 3 | 学校基础套件；开始、暂停／继续、结束 |
| 小型完整 USB 电源 | 1 | 优先使用已有设备，否则自购 |
| 外壳、固定件、连接材料 | 1 套 | 自制；可拆卸安装 |
| R4 Minima 和面包板 | 1 套 | 学校基础套件；台架开发使用，不要求装入最终哑铃 |
| 可导出连续心率记录的参考设备 | 测试时 1 套 | 优先借用胸带类参考设备，用于同步对照测试 |

Nano ESP32 支持 Wi-Fi／BLE，但没有本项目所需的内置运动传感器和 OLED。[Arduino 官方资料](https://docs.arduino.cc/hardware/nano-esp32/)

学校借到的 OLED、心率模块需先核对**具体模块版本、供电和接口电平**，再连接 Nano ESP32。芯片规格不能直接代替转接板规格。

### 结构要求

- 外壳采用可拆卸两端结构，握把连接两端；预留 USB、开关和维修入口。
- 电池与主板可以分置两端，但按实测重量调整布局，不能假设天然平衡。
- 加速度计刚性固定于内部结构，记录轴向；外壳内不得自由晃动。
- 心率传感器置于握把的自然手指接触区域，设置遮光和接触固定结构。
- 第一版不增加训练配重，以电子部件和外壳形成轻量演示原型，目标总质量不超过 1 kg。
- 借用器材采用可拆卸固定，保留完整归还条件。
- 最终 CAD 尺寸依据实物测量确定；先验证传感器接触和内部空间，再制作最终外壳。

### 系统流程

```text
开发阶段：
动作数据采集 → 标注 → 电脑训练与独立测试 → 模型部署到 Nano ESP32

使用阶段：
ADXL335 → 动作分类模型 → 完整周期检测 → 次数
MAX30102 → 信号处理与质量判断 → 心率／无效状态
                                  ↓
                      OLED 显示 + Wi-Fi 传输
                                  ↓
                         电脑实时界面 + CSV
```

**通信默认方案：** Nano 建立本地 Wi-Fi 接入点，电脑连接后使用 HTTP 接口设置会话、获取状态；第一版不依赖校园网络或云服务。

**最小记录字段：**

| 字段 | 含义 |
|---|---|
| `session_id`, `sequence`, `elapsed_ms` | 会话、记录序号、相对时间 |
| `session_state`, `target_reps`, `rep_count` | 会话状态、目标次数、实际次数 |
| `motion_class`, `motion_confidence` | 分类结果与模型置信度 |
| `heart_rate_bpm`, `heart_rate_valid` | 心率；无效时数值为空 |
| `signal_quality`, `connection_state` | 信号质量和连接状态 |

常规状态传输和心率输出目标为每秒一次；心率输出可以基于滚动时间窗口。开发模式额外记录原始加速度和光学数据。

断线期间电脑标记数据缺口；重连后获取当前累计次数，不伪造缺失的历史心率。掉电后的会话标记为中断，第一版不要求恢复未保存数据。

## 4. 验证与验收

以下是初步工程目标，测试前冻结测试方法，避免看到结果后修改标准。

| ID | 测试 | 通过标准 |
|---|---|---|
| AT-01 | 动作分类 | 在未用于训练和调参的测试人员／会话上，三类分类的 macro-F1 ≥ 0.85；报告混淆矩阵。 |
| AT-02 | 弯举计数 | 20 组、每组 10 个完整动作，至少 18 组误差不超过 ±1 次；包含不同速度、暂停和穿插的半次动作。 |
| AT-03 | 干扰动作 | 20 次预先定义的拿起、放下、无关摆动测试，至少 18 次不产生错误计数。 |
| AT-04 | 运动中心率 | 至少 5 名测试者，各完成一段 60 秒连续演示动作；初始稳定时间最多 20 秒，之后逐秒对比同步参考心率。 |
| AT-05 | 心率质量 | 每名测试者有效输出覆盖率 ≥ 90%，有效输出的平均绝对误差 ≤ 10 bpm；同时报告覆盖率和误差，不能只挑选读数好的片段。 |
| AT-06 | 接触丢失 | 手指离开传感器后，2 秒内标记无效；不得用上一个有效值充当实时读数。 |
| AT-07 | 多功能并行 | 连续运行 10 分钟，心率、识别、显示、传输同时开启，无复位或死机；记录采样丢失情况。 |
| AT-08 | 网络中断 | 断开电脑连接 30 秒，本地计数继续；重连后累计次数一致，记录中可辨认断线区间。 |
| AT-09 | 易用性 | 一次演示后，5 名测试者中至少 4 名能在 2 分钟内启动会话。 |
| AT-10 | 机械与续航 | 完成 100 次轻量演示动作，无部件松脱、传感器移位或握把连接松动；无线工作至少 30 分钟。 |

训练、验证和测试按**人员或完整录制会话**划分；不能把同一次录制中高度重叠的窗口随机分散到训练集与测试集。

运动会引入光学测量干扰，因此 **AT-04～06 是最早需要验证的高风险项目**。[Analog Devices 误差说明](https://www.analog.com/en/resources/design-notes/how-common-noise-and-error-sources-affect-optical-biosensing.html)

未借到参考设备时，心率功能可以开发，但不能标记为“准确性已验收”。静止测试通过也不能替代运动测试。

## 5. 预算、工作顺序与交付物

### 初步预算分配

| 项目 | 预算 CAD |
|---|---:|
| Nano ESP32 | 28 |
| USB 电源 | 15 |
| 外壳制作与固定件 | 20 |
| 补充连接材料 | 8 |
| 税、运费和调整余量 | 29 |
| **总上限** | **100** |

预算成立的前提是学校传感器和 OLED 可借、参考设备可借、电脑已有。外壳费用是分配额度，不是打印报价；若实际费用超限，应先调整采购或申请增加预算，不默认超支。

### 工作顺序

1. **需求与市场调研：** 一人整理 CCCARE 需求、比较 3–4 个现有方案，输出需求依据和设计差异。
2. **技术与器材调研：** 一人确认借用品版本、模型部署路径、心率采样方式和实际采购价格。
3. **可行性验证：** 优先测试“运动中握把心率”和“ADXL335 动作分类／计数”，保留原始数据。
4. **台架整合：** 在最终主控上同时运行模型、心率、屏幕和无线记录。
5. **外壳制作：** 按已验证的传感器位置和实物尺寸完成空心结构，再重新采集必要数据。
6. **完整验收：** 按 AT-01～10 测试，记录通过、失败和未测试项。

**最终交付：** 一只原型、固件、训练脚本与模型、电脑记录程序、BOM、外壳文件、测试数据和结果报告。

本版必须保留全部已选功能。若运动中心率、模型识别或预算条件无法达标，应明确提出规格变更，由小组决定；不得把未完成的功能描述为已实现。
