# Contributing

The [team repository guide](docs/team-guide.md) is the practical workflow for this project.

1. Read the current specification and relevant module README.
2. Create or claim one issue with a clear owner and acceptance criterion.
3. Start a short task branch from the current `main`.
4. Keep changes focused; update affected specifications, interfaces and hardware assumptions.
5. Record actual validation and remaining uncertainty. Never claim unperformed hardware tests.
6. Push the branch and open a pull request. Ask a teammate to review before merging.
7. Pull the merged version before starting the next task.

Use a single editor for each CAD/PPTX version. Keep the Markdown specification as the working baseline, dated exports as snapshots, and README links pointing to the accepted current files.

Do not commit credentials, participant identifiers, private health records or unapproved third-party course material. Raw recordings are ignored by default. Public visibility is not an open-source license.

Repository initialization and first-time collaboration-document setup are bootstrap exceptions. Normal subsequent changes follow the PR workflow unless the user explicitly directs otherwise.
